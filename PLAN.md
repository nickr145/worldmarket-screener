# PLAN: Cross-industry market-attractiveness screener

> **Note.** This file is a working log and the registered evaluation protocol, kept as written while the project was built. It refers to raw data caches and firm-level tables (per-firm panels, firm lists, fetch logs) that are not included in this repository; the pipeline regenerates them (see the README).

Decisions locked in: primary target = forward **real** revenue growth (local-currency revenue deflated by country CPI), USD-converted growth as a sensitivity check; leave-country-out CV; per-industry verdicts; free data only; Anthropic API for parse/narrate only; run locally via `streamlit run screener/app/app.py` (no hosting, no public-key concerns).

## 0. Context
An earlier market-scoring case project scored 13 retail/e-commerce markets. The model was weak (RMSE 0.162 vs 0.179, OOF R² 0.16) because of only 13 countries. This expansion turns it into a 4-industry, ~32-country screening tool: free-text company description -> structured profile -> ML scores per country -> expand / consider / avoid with SHAP explanations. Output is a screen, not advice.

## 2. Data sources, features, gaps

**Company universe and financials (all industries)**
- Discovery: `yfinance` `yf.screen` / `EquityQuery` filtered by region, sector/industry, market cap (free, capped at 250 per query so page by exchange and cap bands). Fallback: exchange listing files (NASDAQ Trader, HKEX, NSE, etc.). Spike in Week 1: confirm coverage of the 32 countries.
- Financials: yfinance annual statements (only ~4-5 FYs; main constraint), SEC EDGAR XBRL `companyfacts` for US filers (free, 10+ years, 10 req/s with declared User-Agent) as a deeper cross-check on US cells. FMP free tier (250 calls/day, mostly US) used only for spot validation.
- Prices: yfinance daily back to 2015 (deep enough for the downside-risk target).
- Currency and inflation: growth is computed in local currency, then deflated by country CPI (World Bank `FP.CPI.TOTL`, IMF WEO as backup) to get **real** growth. Nominal local growth in Argentina, Turkey, Nigeria and Egypt is mostly inflation and would wrongly top the "expand" list. USD-converted growth (year-end FX from `PA.NUS.FCRF`) is computed as a sensitivity check only; USD is also used for market-cap ranking.

**Macro / structural (free):** World Bank WDI (CPI for the deflator, GDP, GDP pc, population, urbanization, internet, mobile, FDI, trade, credit), IMF WEO (GDP growth, inflation, current account, forecasts only if as-of-dated), World Bank Findex (account ownership, digital payments; 3-year cadence, forward-fill), ITU (broadband, secure servers), WGI governance (rule of law, reg. quality, control of corruption), WB Doing-Business replacement B-READY where available.

**Industry-specific features (config-driven, one YAML per industry)**
| Industry | Features |
|---|---|
| Non-bank financial services (`non_bank_financials`; excludes Banks, Insurance) | account ownership, digital payments %, domestic credit to private sector % GDP, bank concentration/NPL ratio, remittances % GDP, mobile subs, WGI reg. quality |
| Software & IT | internet users, secure internet servers/million, broadband subs, ICT service exports % GDP, R&D % GDP, tertiary enrolment, WGI |
| Retail / e-commerce | internet users, urbanization, GDP pc, household consumption % GDP, mobile subs, logistics performance index (LPI), account ownership |
| Healthcare / pharma | health expenditure % GDP and per capita, out-of-pocket share, population 65+ %, physicians/1000, hospital beds, life expectancy |
Shared across all: GDP pc, GDP growth, inflation, population, FDI, governance, FX volatility, plus the blue-ocean feature below.

**Gaps and caveats:** Findex and LPI are sparse (3-5 yr cadence): forward-fill with an age feature. Nigeria/Egypt/Vietnam macro series lag. Hong Kong, Taiwan and (partly) Argentina have gaps in WB/IMF. Taiwan is not in WB: use the IMF/DGBAS fallback, time-boxed to Week 2; if it is not clean by then, drop Taiwan. Rate limits: World Bank is fine; yfinance is unofficial and rate-limits (cache every raw pull to parquet, never re-fetch). Licensing: all raw data is free but redistribution varies; commit only derived/aggregated tables plus scripts, not raw yfinance dumps.

## 4. Panel / dataset schema
- **Row = (country, industry, as_of_year t).** Row count, recomputed honestly: yfinance gives ~4-5 fiscal years. Trailing growth at t needs FY t-1 and FY t; the h=2 target needs FY t+2; so each as-of year needs FY t-1..t+2 (4 consecutive FYs). With 4-5 FYs that leaves **1-2 as-of years** (h=1 gives 2-3). 128 cells x 1-2 as-of years, minus `insufficient_data` cells, gives an expected **~150-300 rows**, not 500-600. EDGAR deepens only the US cells.
- **Effective sample size is ~32, not 150-300.** Macro features are country-level and identical across a country's industries and as-of years, so rows within a country are not independent. All uncertainty (CIs, bootstrap) is computed over countries, and the README says so.
- **Universe per cell:** all listed firms mapped to the cell (country of listing + yfinance industry mapped via config), ranked by market cap at t-1, top N (default 25). Cell needs >= 5 firms with valid financials else `status = insufficient_data` (kept in the panel for display, never predicted).
- **Target (growth, PRIMARY):** median across the cell's firms of **real** revenue CAGR from FY t to FY t+h (local-currency revenue deflated by country CPI), h in {1,2}, primary label h=2. Median, winsorised at 1/99%. Sensitivity check: the same target on USD-converted revenue, reported alongside; large disagreement flags FX-driven cells.
- **Target (growth, SECONDARY, exploratory):** forward cell-index return from price history (2015+), over t+1..t+2, which gives many more as-of years for the time-split. **This reflects valuation changes (multiple expansion/contraction) as well as fundamentals**, so it is labelled exploratory everywhere it appears, never used for verdicts, and only reported as a robustness/time-split check on the primary.
- **Target (downside):** (a) primary: forward realised downside of the equal-weight cell index from daily prices over t+1..t+2 (max drawdown and annualised downside deviation), long history so more windows; (b) comparison: quantile XGBoost at q=0.1 on the growth target.
- **Features (all known at t), capped at 6-8 per model** (chosen per industry from the config lists, with the shared set; ~32 effective countries cannot support more): macro as-of t (value at year t-1 or latest published before the cut-off, with a "data age" feature), cell fundamentals at t (median op. margin, net margin, trailing revenue growth, leverage), cell structure (n_firms, concentration/HHI of top-N revenue).
- **Blue-ocean features:** `firms_per_gdp` (listed-company count / GDP in $bn), `firms_per_capita`, and `cell_mktcap_to_gdp`. Plus a country-level control `total_listed_firms_per_gdp`, so SHAP can separate "thin sector" from "thin exchange". Not hard-coded to a sign.
- **Leakage safeguards:** (1) every feature carries an `as_of` date and the builder refuses values dated after t; (2) the membership list is ranked on t-1 market cap only; (3) trailing growth uses FY <= t only and the target uses FY > t only; (4) the top-N is on market cap but market-size proxies (GDP) in features are checked via a correlation report to flag mechanical overlap; (5) every financial feature is dated `as_of_date = fiscal_year_end + filing_lag_days` (default 120, per-country override) and the builder uses `as_of_date`, never fiscal_year_end (`screener/tests/test_fiscal.py` covers the rule; the panel-level planted-future-value test is Week 3); (5b) a unit test builds a panel on synthetic data with a planted future value and asserts it never enters features; (6) survivorship: yfinance only holds current listings. Mitigation: document it, report a "delisted unknown" bias note, and use SEC EDGAR for US cells to quantify how much it changes the target as a sensitivity check.
- Currency/accounting comparability: use growth and margin ratios only (unit-free); flag IFRS vs US-GAAP; no cross-country absolute comparisons.

## 5. Modelling plan
- **Baselines:** (1) global training-mean; (2) per-industry mean; (3) trailing-growth persistence (target ~ last year's growth); (4) ridge on macro features (also a candidate model, see below); (5) old model features on the 13 original countries.
- **Models:** **ridge is a first-class candidate, not just a baseline**; it competes on equal terms with XGBoost and LightGBM (shallow: depth 2-3, strong regularisation, monotone constraints off by default). Every model is capped at 6-8 features. Country-level sample weights so large markets do not dominate. One model with industry as a categorical, vs one per industry; keep whichever wins on leave-country-out, and prefer ridge on a tie (simpler, more stable at ~32 countries).
- **Validation (no random splits):**
  - A. Leave-country-out CV (grouped by country; all 4 industries of a country held out together).
  - B. Time-based expanding window: train on as-of years <= T, test on T+1 (2-3 folds; thin given yfinance history, so reported with wide CIs and labelled exploratory).
  - C. Combined check: leave-country-out within the last as-of year only.
  - Metrics: RMSE, MAE, out-of-fold R², Spearman rank correlation of predicted vs actual (ranking is the product), top-k hit rate (does the predicted top-third beat the bottom-third?), and each reported with a bootstrap CI over countries. Everything compared against the baselines above. A negative result is a valid, reportable result.
- **Downside / intervals:** quantile XGBoost (q10, q50, q90) plus split-conformal intervals on leave-country-out residuals; coverage check (does the nominal 80% interval cover ~80%?). Calibration plot.
- **Verdict rule (fixed up front, not tuned to the output), per industry:** thresholds are **relative to the per-industry median** of predicted real growth and downside risk (not cross-industry, since healthcare and software growth regimes differ). `expand` = growth above its industry median and downside below its industry median; `avoid` = growth below and downside above, or q10 below a floor; `consider` = otherwise. **If the prediction interval straddles the threshold, downgrade to `consider`; wide intervals (width above the registered cut in `settings.yaml`) default to `consider` whatever the ranking.** Cells where one firm is >60% of revenue are flagged **low confidence** (still scored). `insufficient_data` is a separate fourth state. All thresholds (percentile cut, floor, concentration limit) live in `settings.yaml`.
- **Explainability (superseded by the shipped-model spec, see Week 5):** no SHAP unless a boosted model is promoted. The shipped point estimate is ridge, so its explanation is the exact linear contribution of each standardised feature (coefficient x value, plus intercept), which sums to the prediction. The original SHAP plan (waterfall, beeswarm, `firms_per_gdp` x exchange-depth interaction) applies only if a boosted model is promoted. `docs/signs.md` (expected vs observed coefficient sign, catch-up-growth warning) is kept, using ridge coefficients.
- **Old vs new:** report the 13-country retail subset under old and new models.

## 6. Prompt -> profile parser (LLM kept out of prediction)
- `parse/schema.py`: pydantic `CompanyProfile`: `industry` (enum of the 4, or `unsupported`), `home_country`, `revenue_usd`, `operating_margin`, `size_band` (derived), `existing_markets[]` (ISO codes), `business_model` (optional), `confidence`, `unparsed_notes[]`.
- Parser: one Claude call with a JSON-schema tool-use output (forced tool call), temperature 0, enum-constrained fields, then pydantic validation. Missing fields stay `null` and the UI shows an editable form pre-filled with the parse, so the user confirms before scoring. Unsupported industry -> clear message, no score.
- **Mapping to the model:** the profile does not enter the feature vector as raw text. It does exactly three things: (1) selects the industry model/config, (2) removes `existing_markets` and `home_country` from the candidate list, (3) optionally sets display-only context (size band for the narrative, and a "similar-size firms in this market" lookup). The model scores the country-industry cell. Company-specific numbers are not model inputs because the model was trained on cell-level data, and saying otherwise would be a lie in the UI.
- **LLM boundary:** `model/` never imports `anthropic` (enforced with a test that greps imports). The narrator receives only the verdict, the recent-growth (trailing) signal, the interval and the caveats as JSON and may describe only (1) the recent-growth signal and (2) the uncertainty; it makes **no macro-driver claims** because macro features added no skill over the industry mean. It is instructed to cite only those numbers, and a post-check verifies every number in the narration appears in the input.
- Cost control: cache parses by hash; small model for parsing; one narrative call per scored country, batched.

## Decision-date semantics and old-vs-new overlap
- **Decision date.** As-of year t has decision date D_t = 30 Sep of t+1. For a December year-end filer, D_t falls about nine months into FY t+1, so the **h=1 target (FY t -> FY t+1) is a short-horizon / partial-nowcast target**: three quarters of the target year have already elapsed (and most quarterly results are public) even though the annual figure is not. **h=2 is the genuinely forward target.** h=1 is the pre-registered primary spec because it has the most rows, and the nowcast character is a stated limitation, not a hidden one.
- **Taiwan stays dropped:** only three macro features (IMF inflation, GDP growth, current account) exist for it; no GDP, population, internet or health series.
- **The 13 countries of the earlier project:** AR, BR, CA, CN, DE, GB, ID, IN, JP, KR, PL, SG, US. **12 of the 13 appear as `ok` retail cells in all of as-of 2022-2024**; **Argentina is the only one missing** (1 domestic retail firm; it fails Gate 1 for all four industries). Neither Taiwan nor Australia is in the original 13 (AU retail is also not usable: only 4 firms pass the four-year check). The old-vs-new comparison therefore runs on the 12-country overlap (24 primary-spec retail rows).

## Evaluation protocol (PRE-REGISTERED before any model is run)
Written before the baselines are run (Week 4). Changes after this point are logged as deviations in this section, not edited silently.

**Primary spec:** target = `target_h1` (median real revenue growth, FY t -> t+1), feature set **with trailing growth**, `include_biotechnology: false`, Turkey **excluded from training and scoring metrics** (kept in the panel with the low-confidence flag), rows with `status == ok` only. As-of years available: 2023, 2024.
**Sensitivity runs (each labelled, none is a headline):** (S1) `target_h2`; (S2) no-trailing-growth variant (adds as-of 2022); (S3) USD target (`target_h1_usd`); (S4) TR included in training and metrics; (S5) biotech included (separate universe and panel); (S6) concentrated cells (top-1 share > 60%) excluded; (S7) firms with `domicile_assumed` (Korea) excluded.

**CV:** (A) grouped by country, 10 folds (`GroupKFold`): all as-of years and industries of a country share a fold; (B) leave-region-out (5 regions from `countries.yaml`). (C) Time split, exploratory only: train as-of 2023 -> test as-of 2024 (same countries in both, so it is not independent evidence). Hyper-parameters (ridge alpha) are chosen by an inner country-grouped 5-fold CV inside each training fold only; imputation (median) and scaling are fit on the training fold only.

**Feature lists (fixed here; 8 per industry = 5 industry-specific + 3 shared; `gdp_pc_usd` enters as log; no pruning outside CV folds):**
| Industry | Industry-specific (5) |
|---|---|
| non_bank_financials | account_ownership_pct, credit_private_pct_gdp, bank_npl_pct, mobile_subs_per_100, wgi_reg_quality |
| software | internet_users_pct, secure_servers_per_million, ict_service_exports_pct, rd_pct_gdp, wgi_reg_quality |
| retail | internet_users_pct, urban_pop_pct, household_consumption_pct_gdp, mobile_subs_per_100, lpi_overall |
| healthcare | health_exp_pct_gdp, oop_share_pct, pop_65plus_pct, physicians_per_1000, life_expectancy |
Shared (3): log(gdp_pc_usd), firms_per_gdp (blue-ocean snapshot), trailing_growth. The "ridge on macro features" baseline uses the 5 + log gdp_pc + firms_per_gdp (no trailing growth); "ridge (full)" adds trailing growth and is the first-class ridge candidate. Models are fit per industry (one fixed list each); a pooled industry-categorical model is a later comparison.

**Constant-prediction baselines (added before the boosted runs):** for global mean and industry mean, Spearman and the top-third/bottom-third spread are reported as n/a. A constant (or fold-constant) prediction has no rank information; the negative pooled Spearman seen earlier (about -0.3 to -0.4) is a leave-fold-out-mean artifact: a fold's held-out rows pull the training mean away from them, so predictions anti-correlate with the pooled actuals. It is not skill and not a meaningful comparison point.

**Boosted models, run once as registered (Week 5):** one XGBoost and one LightGBM model per industry on the same 8 fixed features as ridge (full), primary spec, depth 2-3, strong regularisation. Fixed settings: learning rate 0.05, subsample 0.8, colsample 0.8, min child weight / samples 5, seed 0. Hyper-parameter grid, tuned INSIDE each training fold by country-grouped 5-fold CV (nested), 8 combinations: max_depth {2, 3} x n_estimators {50, 150} x L2 reg_lambda {5, 20}. NaNs are handled natively (no imputation). CV: country-grouped (10 folds) decides; leave-region-out is reported alongside as a robustness view. No SHAP until promotion is decided.

**Promotion rule (registered before any boosted model is run).** A boosted model replaces the baselines in the app only if BOTH hold under country-grouped CV, using a paired country-clustered bootstrap (the same 1,000 resampled country sets are applied to the model and the baseline; 95% percentile interval of the metric DIFFERENCE):
(a) versus ridge with trailing growth, on RMSE: (RMSE_ridge - RMSE_model) has a 95% interval entirely above zero;
(b) versus trailing-growth persistence, on Spearman: (Spearman_model - Spearman_persistence) has a 95% interval entirely above zero.
An interval that includes zero, or any result in the baseline's favour, is inconclusive/negative, and **an inconclusive result means the baselines are the shipped models.** There is no second try with a different grid or feature list; any later modelling choice is logged as a deviation.

**Baselines (Week 4):** global training mean; per-industry training mean; trailing-growth persistence (prediction = the cell's trailing real growth, no fitting); ridge on macro features. **Models (later, not yet run):** ridge (full), XGBoost, LightGBM.
**Metrics:** RMSE, MAE, out-of-fold R2 (1 - SSE/SST over all out-of-fold rows, SST around the pooled mean of actuals), Spearman rank correlation (pooled), and the **top-third minus bottom-third spread** (terciles of the predictions within industry x as-of year; spread = mean actual growth of the top third minus the bottom third). **Uncertainty:** country-clustered bootstrap (resample countries with replacement, 1,000 draws, 95% percentile CI) over the out-of-fold predictions. A negative result is reportable.

## Verdict rule v1 (final) and v2 (registered Week 7, labelled post-hoc revision)
**v1 result, final for v1:** under the rule "per-industry medians; interval straddling the threshold -> consider", 97 of 97 scored cells are `consider` (3 insufficient data). The 80% conformal half-widths (growth 0.067, downside deviation 0.034) exceed the spread between cells. This is expected: a conformal interval is a prediction interval for one cell's realized outcome, which cannot clear a median threshold at this skill level, while the evidence we have (Spearman 0.53 growth, 0.67 downside; tercile spreads) is about group-level ranking. v1's output is kept in `reports/scored_cells_v1.csv`.

**Verdict rule v2 (post-hoc, written after seeing the v1 result and BEFORE the v2 evaluation is run; thresholds are not to be adjusted after seeing results).** Persistence drives all verdict logic; ridge + conformal intervals are display-only estimates. Within each industry (and within each as-of cross-section when evaluated historically), among eligible cells (scored, not Turkey), with rank percentile pct = (rank - 1) / (n - 1) over the cell's signal and "top third" meaning pct >= 2/3:
- **Avoid:** top third of the downside-deviation signal (trailing 12-month downside deviation; highest = riskiest).
- **Expand:** top third of the growth signal (trailing real growth) AND not in the top third on downside deviation.
- **Consider:** everything else. `insufficient_data`, Turkey (low-confidence, forced to `consider`), concentrated cells and `domicile_assumed` flags carry over unchanged as display flags.

**Pass criterion for shipping verdict labels (registered).** Apply v2 to the historical cross-sections (persistence has no fitted parameters, so out-of-fold under country-grouped CV equals the signal itself; ranks use only same-cross-section data known at the decision date). Evaluation samples: (avoid) as-of 2022-2024 cell-years with a downside signal and realized 12-month downside deviation; (expand/consider) as-of 2023-2024 cell-years with trailing growth, realized real growth (`target_h1`), and the downside pair (as-of 2022 has no trailing growth). Realized outcomes are demeaned within industry x as-of year before comparison (tiers are within-industry; this removes industry/year level effects); raw tier means are also reported. Uncertainty: country-clustered bootstrap, 1,000 draws, seed 0, 95% percentile intervals. **All three must hold:** (1) mean realized downside deviation of `avoid` cells minus all other cells has a 95% CI above zero; (2) mean realized growth of `expand` cells minus `consider`+`avoid` cells has a 95% CI above zero; (3) mean realized downside deviation of `expand` cells is no worse than the rest (point estimate of expand minus rest <= 0). **If the criterion fails, ship rankings + intervals with NO verdict labels** (`verdict = unranked`).

**Also registered (Week 7):** (a) growth conformal intervals are INDUSTRY-specific (half-width from that industry's leave-country-out residuals, finite-sample quantile at 80%); an industry whose empirical leave-country-out coverage falls outside [0.70, 0.90] is marked `intervals unreliable` in `scored_cells.csv` (`interval_reliable = False`). (b) Freshness: for each cell, `data_freshness` = share of the cell's fetched firms with a known FY2024 figure that also have FY2025 known by the 2025 decision date (a firm lacking FY2025 falls out of the as-of 2025 membership, i.e. its cell is built from the firms that do have FY2025, not from a FY2024 fallback); cells below 60% are flagged `stale_firms_flag`.

**v2 evaluation result (run once, exactly as registered; reports/verdict_v2_eval.csv, reports/verdict_v2_decision.json): the pass criterion is MET, so v2 labels ship.** Realized outcomes by tier (raw means, country-clustered 95% CI): `avoid` cells 12-month downside deviation 0.158 [0.146, 0.169] (88 cell-years, as-of 2022-2024) vs `consider` 0.116 [0.107, 0.126] and `expand` 0.122 [0.108, 0.140]; on the joint 2023-2024 sample realized real growth is `expand` 8.6% [6.3, 10.9] vs `consider` 3.9% [2.4, 5.2] and `avoid` 3.8% [2.2, 6.1]. Registered tests (demeaned within industry x as-of year, tier minus rest): (1) avoid downside +0.041 [+0.026, +0.055] PASS; (2) expand growth +0.046 [+0.023, +0.071] PASS; (3) expand downside -0.017 [-0.031, -0.002] PASS (point <= 0). Caveats: only two as-of years (2023-2024) carry the growth test (40 `expand` cell-years, 28 countries); criterion (3) is partly mechanical because `expand` excludes the top downside third; thresholds were set before the evaluation and not adjusted. Tier counts per industry in the joint sample (avoid/consider/expand): healthcare 16/21/11, non-bank financials 10/14/8, retail 16/17/11, software 15/21/10.

## Scope limits
The screener only covers countries with listed-market depth. Universe rules: primary exchanges only; firms deduplicated by name within a country (yfinance exposes no usable ISIN); a firm counts only if its domicile equals the listing country (Korea's unresolved KOSDAQ/KOSPI domiciles are assumed domestic and flagged `domicile_assumed`). Frontier markets (and the dropped countries: AE, CO, EG, PH, VN have zero screener coverage; IE has none either; Nigeria and Kenya have no yfinance region; Taiwan lacks structural macro data; Argentina is configured but has fewer than 5 domestic listed firms in every industry, so it has no cell in the panel) are absent or fall out as `insufficient_data`, so the blue-ocean (thin-listed-market) test only covers countries above the minimum-firms threshold. It cannot say anything about markets with no listed depth, and a thin cell in a covered country is not evidence of whitespace elsewhere.

Further limits. (a) **Target years are fiscal 2023-2025 only** (as-of 2022-2024, base years FY2022-FY2024): the post-pandemic inflation and rate regime, so nothing here says how the model behaves in other regimes. (b) **Survivorship:** a firm needs at least four consecutive fiscal years of revenue, which excludes recent listings, and yfinance holds current listings only. (c) **Korea healthcare sampling (corrected 2026-10-16):** 57 of the 60 fetched firms have four fiscal years of revenue and CPI, and the cell has 25 members in every as-of year, so it is not thin. An earlier figure of 32 of 60 matches the number of Korea healthcare firms cached before the financials fetch finished (32 at 00:25 on 2026-10-08, the stale selection-sensitivity state), so it probably came from that incomplete cache. Two more. (1) **Listed-firm growth reflects global revenue, not home-market demand**: a listed firm's revenue growth comes from everywhere it sells (a Swiss pharma or an HK-listed firm with mainland operations), so the target measures how listed firms domiciled in a country grow, not how fast demand grows inside that country. (2) **Blue-ocean counts are a current snapshot**: `n_listed_cell`, `firms_per_gdp`, `firms_per_capita`, `cell_mktcap_to_gdp` and `country_listed_4ind_per_gdp` use today's listings and market caps (uncapped), not as-of-dated values, and carry survivorship. They are flagged `SNAPSHOT_COLS` in the panel builder.

## Deviation, 2026-10-15: financial-currency tag error (HCLTECH.NS), one override, rerun once as registered
**Bug.** HCLTECH.NS carries `financial_currency = USD` in the yfinance financials cache, but its reported revenue (1.30e12) is in INR. The panel therefore applied FX = 1.0 and deflated by US CPI, which made HCL 94.5% of India software's top-25 revenue (cell flagged concentrated / low confidence in all four as-of years). Found by the concentration audit during the display-label pass; the other 18 concentrated cells are consistent with their tags.

**Evidence.** The tag differs from the listing currency (INR); revenue, total assets, equity and net income per USD of market cap are 4 of 4 about 100x the cell median under USD (composite +2.00) and within 0.1 log10 of it under INR (+0.06); the FX gap is 87x; external confirmation from HCLTech's FY26 results release (revenue Rs 130,144 crore, USD revenue $14.7 billion; https://www.hcltech.com/en-us/press-releases/hcltech-fy26-revenue-39-led-increasing-demand-advanced-ai).

**Change.** Exactly one override, HCLTECH.NS USD -> INR, as one row of `data/panel/currency_overrides.csv` (read by `run_panel.prepare`). A tag-free anomaly check (`screener/clean/currency_check.py`: tag differs from listing currency; composite at least 10x off under the tag; another currency within +/-0.3; FX gap at least 10x; at least 3 of 4 metrics within 0.5 log) runs on every panel build and prints candidates. It is **report-only and never applies anything.** Three weaker cases (6467.TWO, 7781.TWO, ASTR.BK: tag equals listing currency, magnitude fits USD) and seven tag-differs-from-listing firms that fit no currency are listed for review and **not** changed. No new grids, features, thresholds or tuning; the registered protocol and promotion rules apply unchanged.

**Plan.** Control run first (full chain, empty override table, must reproduce the shipped `scored_cells.csv` byte for byte), then one run with the single override, with the panel, baselines, boosted models under the registered promotion rule, risk targets, the registered v2 verdict criterion, industry-specific conformal intervals, live scoring and the 40-cell narrator holdout. New artifacts are written under new file names (`*_v1_1`, `models/shipped_v1_1/`, tag `shipped-v1.1`); `models/shipped_v1`, `reports/scored_cells.csv` and the v1 tag are left as the record of the first run. A shadow run on a copy of the repository before this change estimated about 27 changed `scored_cells` rows, all software, no verdict changes and no top-25 membership changes. **The corrected data is adopted regardless of how the results come out.**

**Limitations found by the audit (not fixed).** (a) Firm-years with revenue but no FX rate (11 Turkish, 3 Korean) are dropped from membership. (b) Where the tag and listing currencies are within about 3x of each other, magnitude cannot verify the tag; a wrong tag there is bounded at about 1.5x. Eight firms near their cell's top-25 cutoff are in that position: 0162.HK, 8329.HK, 2348.HK, 8049.HK, 8205.HK, CPH.TO, HLS.TO, DUG.AX.
